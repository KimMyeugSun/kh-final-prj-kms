📌 프로젝트 개요

개발 형태: 팀 프로젝트

프로젝트 목적:
직원 건강 데이터를 체계적으로 관리하고,
설문 기반 데이터 수집과 커뮤니티 기능을 하나의 시스템으로 통합하는 것을 목표로 했다.

🧨 트러블슈팅
1. 복잡한 연관관계로 인한 조회 구조 문제

문제 상황
리서치 결과 조회 시 다수의 엔티티가 연관되어 있어 JPA 기본 조회 방식으로는 쿼리 구조가 복잡해지고, 화면에 필요하지 않은 데이터까지 함께 조회되는 문제가 발생했다.

해결 과정

QueryDSL을 도입하여 조회 로직을 재구성했다.

화면에 필요한 데이터만 조회하도록 DTO 기반 쿼리를 작성했다.

join 구조를 명시적으로 표현하여 쿼리 흐름을 파악하기 쉽게 개선했다.

결과

조회 쿼리의 의도가 명확해졌다.

불필요한 데이터 로딩이 제거되었다.

유지보수성과 가독성이 향상되었다.

2. 설문(리서치) 응답 중복 처리 문제

문제 상황
동일 사용자가 같은 설문에 여러 번 응답할 수 있는 구조로 인해 데이터 중복이 발생할 가능성이 있었고, 결과 집계의 신뢰도가 떨어질 우려가 있었다.

해결 과정

사용자와 설문을 기준으로 응답 정책을 정의했다.

중복 응답을 방지할 수 있도록 데이터 구조를 재설계했다.

응답 이력 개념을 도입하여 회차별 관리가 가능하도록 개선했다.

결과

데이터 무결성이 확보되었다.

설문 결과의 신뢰도가 향상되었다.

재응답 허용과 같은 요구사항에도 대응 가능한 구조가 되었다.

3. 팀 협업 과정에서의 기능 경계 충돌 문제

문제 상황
게시판과 리서치 기능이 확장되면서 도메인 책임이 모호해지고, 팀원 간 구현 영역이 겹치는 문제가 발생했다.

해결 과정

기능 중심이 아닌 도메인 기준으로 역할을 재정리했다.

엔티티별 책임 범위를 명확히 정의했다.

공통 로직과 개별 기능 로직을 분리했다.

결과

코드 충돌이 줄어들었다.

기능 수정 시 영향 범위를 예측하기 쉬워졌다.

팀 협업 효율이 개선되었다.

4. 기능 중심 코드에서 설명 가능한 구조로 개선

문제 상황
초기 구현 단계에서는 기능 동작 위주로 개발되어 코드 구조와 의도를 설명하기 어려운 부분이 존재했다.

해결 과정

메서드 단위의 책임을 재정의했다.

의미 있는 네이밍과 계층 분리를 적용했다.

면접에서 설명 가능한 구조를 기준으로 리팩토링을 진행했다.

결과

코드 가독성이 향상되었다.

기능 설명이 쉬워졌다.

유지보수 관점에서 안정성이 개선되었다.

# 🧩 사내 건강 관리 웹 서비스  
Final Team Project

> **사내 구성원의 건강 데이터를 설문·게시판·커뮤니티 기능으로 통합 관리하며,  
권한·데이터 무결성·협업 구조를 중심으로 설계한 실무형 웹 서비스**

---

## 📌 프로젝트 개요
KH정보교육원 교육 과정 중 **6주간 진행한 파이널 팀 프로젝트**로,  
사내 구성원의 **건강 정보 관리와 커뮤니티 기능을 결합한 웹 서비스**를 구현했다.

- **개발 기간**: 2025.08.25 ~ 2025.10.10  
- **개발 형태**: 팀 프로젝트  
- **프로젝트 목적**
  - 직원 건강 데이터를 체계적으로 관리
  - 설문 기반 데이터 수집과 커뮤니티 기능을 하나의 시스템으로 통합
(참고 사항 : 프로젝트를 진행한 실제 깃허브 링크가 아닌 복사본이며, aws 및 cicd 기능은 코드가 있으나 실행이 되지 않게 함)

## 🧨 트러블슈팅

### ⭐ 대표 사례: 복잡한 연관관계로 인한 조회 구조 문제
**문제 상황**
- 리서치 결과 조회 시 다수의 엔티티가 연관되어 있어
  JPA 기본 조회 방식으로는 쿼리 구조가 복잡해지고
  화면에 필요하지 않은 데이터까지 함께 조회되는 문제가 발생했다.

**해결 과정**
- QueryDSL을 도입하여 조회 로직을 재구성했다.
- 화면에 필요한 데이터만 조회하도록 DTO 기반 쿼리를 작성했다.
- join 구조를 명시적으로 표현하여 조회 흐름을 파악하기 쉽게 개선했다.

**결과**
- 조회 쿼리의 의도가 명확해졌다.
- 불필요한 데이터 로딩이 제거되었다.
- 유지보수성과 가독성이 향상되었다.

---

### 2. 설문(리서치) 응답 중복 처리 문제
**문제 상황**
- 동일 사용자가 같은 설문에 여러 번 응답 가능한 구조로 인해
  데이터 중복 및 결과 신뢰도 저하 우려가 있었다.

**해결 과정**
- 사용자 + 설문 기준으로 응답 정책을 정의했다.
- 중복 응답 방지를 위한 데이터 구조를 재설계했다.
- 응답 이력 개념을 도입했다.

**결과**
- 데이터 무결성이 확보되었다.
- 재응답 허용 등 확장 요구사항에도 대응 가능한 구조가 되었다.

---

### 3. 팀 협업 과정에서의 기능 경계 충돌 문제
**문제 상황**
- 게시판과 리서치 기능 확장 과정에서
  도메인 책임이 모호해지고 팀원 간 구현 영역 충돌이 발생했다.

**해결 과정**
- 도메인 기준으로 역할을 재정의했다.
- 엔티티 책임 범위를 명확히 정의했다.
- 공통 로직과 개별 로직을 분리했다.

**결과**
- 코드 충돌이 감소했다.
- 협업 효율과 유지보수성이 개선되었다.

---

### 4. 기능 중심 코드에서 설명 가능한 구조로 개선
**문제 상황**
- 기능 구현 위주의 코드로 인해 구조 설명이 어려웠다.

**해결 과정**
- 메서드 단위 책임을 재정의했다.
- 의미 있는 네이밍과 계층 분리를 적용했다.
- 설명 가능한 구조를 기준으로 리팩토링을 진행했다.

**결과**
- 코드 가독성이 향상되었다.
- 유지보수 안정성이 개선되었다.
